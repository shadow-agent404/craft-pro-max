# craft-pro-max

一个给 AI 编码代理用的技能包：把文案、页面、交付检查写成可判定的规则，而不是"要写得好一点"。

装法一步：把 `craft-pro-max/` 复制到代理的 skills 目录。

## 修什么

- 文案开头是"我们致力于通过领先的智能化解决方案"，结尾接三段排比。
- 落地页固定长成 Hero → 三张卡 → 一排数字 → CTA，换个行业照样成立。
- 代码能跑，但 375px 下横向滚动，Tab 走不到提交按钮，暗色模式没人测对比度。

## 里面有什么

| 文件 | 作用 |
|---|---|
| `SKILL.md` | 常驻规则：输入契约、三层规则、输出格式、验收线 |
| `references/writing-rules.md` | 19 条写作规则，每条给判据、检查方法、反例 |
| `references/design-rules.md` | 30 条设计规则、8 条黑名单、9 项交付自检 |
| `references/build-rules.md` | 开工 5 步、四道交付检查（门禁）、交付说明模板 |
| `references/conflicts.md` | C1–C10 默认值：行宽、字体数量、动效、远端抓取等 |
| `evals/test-prompts.json` | 9 条测试：该调 3 条、边界 3 条、不该调 3 条 |
| `THIRD_PARTY_NOTICES.md` | 改编来源、版权行与 MIT 许可全文 |

## 装

Trae，用户级：

```powershell
Copy-Item craft-pro-max "$env:USERPROFILE\.trae-cn\skills\" -Recurse
```

Trae，项目级（只对这个仓库生效）：

```
<repo>/.trae/skills/craft-pro-max/
```

其他客户端：整个文件夹放进对应的 skills 目录。`SKILL.md` 的 frontmatter 是标准的 `name` + `description`，没有私有字段。

复制被系统拒绝时，先给目标目录写权限，别改成管理员全局运行。写入范围越小越好。

## 用

装好之后不敲命令，按任务类型触发。

1. 它先问 5 项：主体、受众、唯一任务、已知事实、禁区。缺哪项标【待补】，不往下写。
2. 文案任务：挖细节 → 改写 → 终审三遍（删 / 真 / 读）。
3. 设计任务：先出 Design Read（四问单页），再出 ASCII 线框和设计令牌（颜色、字体、间距变量），确认后才写代码。
4. 构建任务：读 `AGENTS.md` → 生成 → 跑四道门禁 → 交收尾清单。

第 4 问是"哪个元素只有这个主体才有"。代理答不出来会停下来要素材。这是它和模板生成器的分界。

## 几条默认值

- 正文行宽：桌面 60–75 字符，移动 35–60，上限 80。
- 字体：每页至少 2 套艺术字体做展示层，正文用 1 套可读体，艺术体不进正文段落。
- 动效：每屏 1–2 个元素，退场时长是入场的 60–70%，整页逐节入场默认关掉。
- 不做远端抓取，规则只读本地 `references/`。
- 两条规则打架且不在 `conflicts.md` 里，先问，不自行合并。

## 测试

`evals/test-prompts.json` 里有 9 条 prompt，每条带 `checks` 和 `fail_if`。

跑法：同一 prompt 各跑一次，开 Skill 与关 Skill 对比四项：

1. 是否先问输入契约
2. 是否出现主体特有的细节
3. 是否触犯黑名单
4. 输出结构是否符合 `SKILL.md` 第 5 节

四项都没差异，说明这个 Skill 对你当前的模型不起作用，别硬留。

## 什么时候别用

- 算数、查天气、问概念：它不接这类任务。
- 技术文档：只保留清晰度规则，营销节奏和删减法停用。
- 纯后端或脚本：只留类型与依赖两条约束。

## 已知限制

- 写作模式改编自两个公开的 MIT 项目，版权与许可写在 `THIRD_PARTY_NOTICES.md`；不逐条标注页码。
- Design Read 第 4 问靠人给素材，代理编不出来。
- eval 靠人工比对两次输出，仓库里没有自动打分脚本。
