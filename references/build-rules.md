# 构建规则（前端质量门禁）

> 用途：栈不熟、不知道该跑哪些检查、交付前收尾时读本文件。
> 所有条目都是项目约定，与具体书籍或第三方 Skill 无关。

---

## 一、开工前（5 分钟，不做完不许写码）

1. **读 `AGENTS.md`**：技术栈、目录结构、组件库、命名约定、禁用依赖。
2. **列已有组件清单**：Button / Input / Modal / Toast / Table 是否已存在，路径写下来。
3. **确认栈**：从 `package.json`、`pubspec.yaml`、`*.xcodeproj` 等实测判断，**不许假设**。
4. **确认渲染目标**：SSR / CSR / 静态导出，决定数据获取与图片优化策略。
5. **确认验收口径**：谁会看、在什么尺寸看、要不要通过 axe。

---

## 二、代码约束

### B1 禁止另起炉灶
- 已有组件必须复用；确需新建，先在回复里写"为什么现有组件不够"，再动手。
- 新组件由简单原语组合，不复制整段样式。

### B2 类型与依赖
- TypeScript 必须带类型，禁止 `any` 兜底（确实未知用 `unknown` + 收窄）。
- 不动依赖版本、不擅自加包；必须加时说明体积与替代方案。

### B3 样式来源单一
- 颜色/间距/字号只从 token 取，组件内禁 raw hex。
- 类名不做动态拼接（影响 purge）。

### B4 语义与可访问性写进结构
- 用语义标签（header/nav/main/section/footer），标题层级不跳级。
- 每个输入有 label，图标按钮有可访问名，装饰图标对辅助技术隐藏。
- 焦点顺序 = 视觉顺序；路由切换后焦点移到主内容。

## 三、性能底线

| 项 | 阈值 |
|---|---|
| 图片格式 | WebP/AVIF + srcset + 非首屏 lazy |
| 尺寸声明 | 必写 width/height 或 aspect-ratio |
| CLS | <0.1 |
| 单帧耗时 | <16ms，重任务移出主线程 |
| 列表 | >50 项虚拟化 |
| 输入延迟 | <100ms，100ms 内给按压反馈 |
| 字体 | `font-display: swap`，只 preload 关键字体 |
| 分包 | 按路由/功能切分 |

## 四、质量门禁（四道，全过才算交付）

### 门禁 1：响应式
- 375 / 768 / 1024 / 1440 四个宽度各看一次；375 与横屏无横向滚动。
- 固定栏不遮内容（滚动区留 padding）。

### 门禁 2：对比度
- 正文 ≥4.5:1，大字 ≥3:1，暗色独立测一遍。
- 可执行：用 axe / Lighthouse 或对比度脚本跑一遍，把数值贴进交付说明。

### 门禁 3：键盘与读屏
- Tab 走完全流程，焦点可见且不被 sticky 元素遮挡。
- 表单错误有 `aria-live` 或 `role="alert"`。

### 门禁 4：三态与动效
- 空 / 错 / 加载三态都有真实文案。
- `prefers-reduced-motion` 下可用；动画只动 transform/opacity。

### 常用命令（按项目实际替换）
```bash
npx axe http://localhost:3000 --exit
npx lighthouse http://localhost:3000 --only-categories=accessibility,performance --chrome-flags="--headless"
npx playwright test
```
> 命令仅作参考，仓库里已有脚本时以仓库脚本为准。

## 六、反幻觉（构建层）

- 不编评价数、星级、执照号、客户名、年份、排名、融资额、用户量。
- 占位内容必须显式标注（`TODO(placeholder)`），不得混进正式文案。
- 任何数字要么来自输入，要么来自可运行代码的计算结果。

---

## 七、什么时候别用本文件

- 纯后端 / CLI / 脚本任务：只保留 B2（类型与依赖）。
- 不产出代码的纯设计评审：只走 `design-rules.md` 的自检表。
