# 写作规则（去 AI 味全量版）

> 用途：文案卡壳、句子不干净、被说"像 AI 写的"时读本文件。
> 每条规则只给三样东西：**判据**（能不能过）、**检查**（怎么验）、**反例**（长什么样算违规）。

---

## 一、句子层

### W1 删废字：每个词都得干活
- **判据**：逐句删词后重读；意思不变 → 那个词就是废的。优先删 `the fact that`、`who is`、`in order to`、同义副词。
- **检查**：首稿字数 ×0.7 后是否更清楚；删三成仍无损，说明初稿不合格。
- **反例**：一段删掉三成词语义完全不变。

### W2 主动语态：能主动就别被动
- **判据**：抽 10 句，被动句 ≤2 句；每个留下的被动句要能说出理由（施动者未知 / 需强调受动者）。
- **检查**：全文检索 `was made by`、`can be seen`、`is used to`。
- **反例**：通篇被动，读者不知道谁做了什么。

### W3 肯定断言：不用 not 绕弯
- **判据**：检索 `not very`、`not important`、`did not remember`，逐处改成反义词或正面陈述；`not` 只保留在真否定与对照。
- **反例**：只告诉读者"不怎样"，不说"是怎样"。

### W4 修饰语贴身，强调词收尾
- **判据**：修饰短语与被修饰词之间不隔名词短语；`only` 紧贴它限定的成分；每段末句承载结论或新信息。
- **反例**：`He only found two mistakes.`（只找到？只两处？）

### W5 打散松散句，一句一意
- **判据**：连续三个以上 and/but 连缀的句子必须重写；一句里出现两个以上转折 → 拆句。
- **检查**：一句里数 `and` / `but` / 逗号串句，超阈值就拆。
- **反例**：一句话里塞进四个并列动作，读者读到一半忘了主语。

## 二、段落层

### W6 一段一主题，首句承重
- **判据**：每段能用一句话概括；段首句承担主题，段尾句给结论或后果；对话换人即换段。

### W7 去 clutter：删不干活的词块
- **判据**：每 500 字里 `at this point in time`、`a personal friend of mine`、空转形容词 ≤2 处（普通初稿基线）。
- **反例**：满篇"值得一提的是""众所周知""在一定程度上"。

### W8 剥离：逐句删
- **判据**：逐句问"我要说什么、说清了吗"；删后朗读更清楚，就保留删版。
- **反例**：用 `experiencing precipitation` 代替 `it may rain`。

### W9 统一：人称、时态、语气各锁一种
- **判据**：标出全文人称/时态/语气切换点；除引语与真实时间跳跃外，每种只保留一个。
- **反例**：同段从 `I went` 切到 `you know`，再切现在时。

### W10 首句只有一个 KPI
- **判据**：首两段内出现硬细节或悬念；删掉首句若信息无损，首句不合格。
- **反例**：开头交代背景、天气、致谢，第三段才入题。

## 三、全篇层

### W11 一个窄切面，不写全景
- **判据**：回忆/案例类写作只取一个场景或一段时间，其余删掉；每 2–3 段至少出现一句当事人原话或一个可核对细节。

### W12 术语必须翻译，读者是旁观者
- **判据**：术语首次出现时同句内给一句人话解释；假设读者一无所知，从一个事实逐句展开。
- **反例**：开篇连用三个内部缩写，读者第三句就掉队。

### W13 具体大于抽象
- **判据**：每个抽象判断后面跟一个可核对的名词或数字；"提升效率"必须换成"从 4 步减到 1 步"。
- **反例**：全篇"赋能、闭环、提效"，读者无法验证任何一句。

### W14 商务写作：谁对谁做了什么
- **判据**：把机构名词拆成"某人 → 对某人 → 做了某事"；句子里必须有能负责的主语。

## 四、网页文案层

### W15 标题即结论
- **判据**：把标题单独拿出来给没看过页面的人读，他能说出这页要他做什么；说不出即不合格。

### W16 一屏一个动作
- **判据**：首屏主按钮 ≤1 个，其余动作视觉降级；同一动作全流程同名（按钮"发布"→ 提示"已发布"）。

### W17 删掉一半，再删一半
- **判据**：`欢迎来到…`、`本页将介绍…`、`使用本网站很简单，只需…` 出现次数必须为 0；删完这些页面仍成立才算合格。

### W18 按扫描写，不按阅读写
- **判据**：每屏有一个可扫的小标题结构；段落 ≤4 行；关键信息在首屏。

### W19 错误文案：说清原因和出口
- **判据**：错误句必须含"发生了什么 + 怎么修"；不道歉、不模糊。
- **反例**：`出错了，请重试。`

## 五、禁刻意修辞清单

| 禁止项 | 判定 |
|---|---|
| 三段排比 + 升华结尾 | 结尾出现"这不仅是…更是…"式拔高 |
| "不是…而是…"模板开头 | 全文 ≥1 次且非纠正具体误解 |
| 三连形容词（"更快、更稳、更智能"） | 无一项可验证 |
| 标题内单词单独变色/斜体/加粗 | 为强调而强调 |
| 全大写标签、eyebrow 小标 | 任何位置 |
| em-dash 连用、emoji 当标点 | 单段 ≥2 处 |
| 空词：factor / feature / case / nature | 无具体所指 |
| 新闻腔：famed / upcoming / 备受瞩目 | — |
| 油滑口语腔（"你懂吧""说白了"） | 朗读时出现 |

## 六、终审三遍（交付前必跑）

1. **删**：逐句删词 → 逐段删句 → 删掉第一段看是否更好。
2. **真**：每个数字、名字、年份能否指回输入或可查来源；不能 → 标【待补】或删。
3. **读**：出声朗读一遍；读不顺的地方就是写错的地方；检查人称/时态是否只锁一种。

三遍任何一遍没过，不许说"完成"。

## 六之二、人味模式（31 条）

终审之后再跑 `humanizer-patterns.md`，那里有完整清单与改前/改后示例。最先看这 6 条：

| 模式 | 判据 |
|---|---|
| 不是 X，而是 Y | 假对比，抬语气；除非否定部分在纠正真实误解 |
| 强凑三段式 | 三项里有一项不提供独立信息 |
| 破折号当万能连接 | 用破折号制造悬念或掩盖分句关系 |
| 意义拔高 | "标志着新时代""彰显了……"没有独立内容 |
| 客服腔 | "好问题！""希望这对您有帮助" |
| 套话收尾 | 祝愿、期待、口号，不含真实计划 |

顺序不能反：先核对事实与确定程度，再改风格。删掉"可能"变成确定，比留一句套话更糟。

## 七、边界（什么时候不套这套）

- 技术文档 / API 说明：保留 W1–W5、W12，停用 W11、W14–W18 的营销节奏与删减法。
- 学术/法务文本：只保留 W1、W3、W4，其余不适用。
- 用户明确要求"模板化/宣传腔"：照做，但在交付里说明牺牲了哪几条。
