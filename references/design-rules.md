# 设计规则（反模板 + IA + 交互全量版）

> 用途：页面平淡、层级乱、像模板、IA 说不清时读本文件。
> 每条规则只给**判据**与**反例**，不给解释性长文；数值即验收线。

---

## 一、Design Read（动手前必须写满 4 行）

| 问题 | 合格答案的样子 |
|---|---|
| 受众第一次看到，要相信什么？ | 一句可被证伪的信念，不是"我们很专业" |
| 这页唯一任务是什么？ | 只有一个动词：预约 / 询价 / 下载 / 订阅 |
| 做成通用 SaaS 模板会错在哪？ | 指出 1 个具体错位（行业、语气、信息密度） |
| 哪个元素只有这个主体才有？ | 一个可指认的物件 / 数字 / 细节 |

第 4 问答不出 → 不许进线框，先补素材。

---

## 二、信息架构（IA）

### D1 先组织，再排版
- **判据**：先交"内容清单 + 分类 + 标签"一页，再交线框；分类维度互斥。
- **反例**：直接画首页，导航里出现"资源/更多/相关"。

### D2 分面必须互斥（正交）
- **判据**：抽任一对象，每个分面下有且仅有一个取值；两个分面能同时取同值即失败。
- **反例**：尺码与颜色压进同一列，筛选里出现"红色加大码"。

### D3 信息气味优先，不设点击数上限
- **判据**：每个链接名，目标用户不看正文就能预测点进去得到什么；能预测则允许深。
- **反例**：为压进 3 次点击把几十个类目塞首页。

### D4 导航：位置固定、层级分明、深页可达
- **判据**：每页同位置出现站点标识、栏目、返回主页、搜索；主导航 ≤5 项；≥1024px 用侧栏；3 层以上加面包屑；深层页仍能回到主导航。
- **反例**：内页只剩 logo，没有栏目条与搜索。

### D5 标签用用户语言
- **判据**：标签词出现在目标用户的访谈原话里；出现"表/字段/模块/事务"等实现词即不合格。

## 三、版式与层级

### D6 亲密性：分组自己说话
- **判据**：眯眼扫一遍，视觉停点 >3–5 处须合并同类项；组间距必须明显大于组内行距。
- **反例**：名片上姓名、地址、电话行距完全相等，读者分不清层级。

### D7 对齐：一条线
- **判据**：全页文本对齐方式 ≤1 种；居中仅用于明确的正式场景。
- **反例**：卡片上同时居中标题、左对齐地址、右对齐电话。

### D8 重复：母题贯穿
- **判据**：多页文档每页 ≥3 处位置固定、样式一致的重复元素。
- **反例**：每页标题字体字号各不同，翻页认不出是同一份文件。

### D9 对比：不相同就截然不同
- **判据**：字号/线宽/色值任一维度须一眼看出主次；12 磅 vs 14 磅、0.5 磅 vs 1 磅判失败。
- **反例**：深棕正文配黑标题，远看像印刷偏色。

### D10 间距与栅格
- **判据**：间距取 4/8 增量（4,8,12,16,24,32,48,64）；桌面容器有统一 max-width；z-index 分层命名。

### D11 行宽
- **判据**：**桌面正文 60–75 字符，移动 35–60，任何正文不超过 80**。
- **反例**：整屏正文横向铺到 110 字符，读者换行时找不到下一行。

## 四、字体

### D12 多艺术字体（项目硬约束）
- **判据**：每页必须使用 **≥2 套艺术字体**承担展示层（大标题 / 引语 / 数字 / 标签 / 签名元素），正文仍是 1 套高可读字体；艺术体禁止用于正文段落。
- **可执行**：交付时列出字体清单，至少 2 个非默认展示体，各自写明用途；不得用系统默认族冒充艺术体。
- **可读性底线**：正文 ≥16px、行高 1.5–1.75、行宽按 D11。
- **反例**：全站只用一个系统无衬线字体，标题与正文仅差字号。

### D13 字阶与行高
- **判据**：字阶取 12/14/16/18/24/32 一类固定序列；正文行高 1.5–1.75；serif 正文行高略高于 sans；正文最小 16px（移动）。

### D14 字体对比六轴
- **判据**：需要对比时从大小/粗细/结构/形状/方向/颜色六轴里选 ≥1 轴做足；两种相似字体同页 = 冲突。
- **反例**：标题用 Medium、正文用 Regular 的同族字，层级几乎看不出。

### D15 排版细节
- **判据**：标点后一个空格；用弯引号与真撇号；不用下划线做强调；避免全大写长句；检查寡妇/孤儿（末行 <7 字符须重排）。

## 五、颜色

### D16 命名色板 4–6 个
- **判据**：每个色有名字与用途（bg / surface / text / muted / accent / danger）；组件里不出现 raw hex。

### D17 三层 token
- **判据**：primitive（原始色阶）→ semantic（bg/text/accent/danger）→ component（button-bg 等）；semantic 层支持明暗切换。

### D18 对比与暗色
- **判据**：正文 ≥4.5:1，大字 ≥3:1；暗色用去饱和的浅色调，而非反相；暗色单独测对比。
- **反例**：暗色模式直接把配色取反，图片与图表全部刺眼。

### D19 颜色不作唯一通道
- **判据**：状态/分类若仅靠颜色区分即不合格；须加文字、图标或形状。
- **反例**：红绿点表示在线/离线，无文字标签。

## 六、交互

### D20 示能与意符分开
- **判据**：遮住文字标签，让没用过的人指出下一步操作位置；指错或明显迟疑 = 意符缺失。
- **反例**：玻璃门去掉铰链与推板，靠贴"拉"字补救。

### D21 反馈不打断流
- **判据**：常态信息用常驻状态条/行内提示；模态框只用于必须立刻决断；>10s 任务可取消、可转后台。
- **反例**：每次保存成功都弹"保存成功！"

### D22 少提问，多给选择
- **判据**：一次典型任务的模态提问目标为 0；必须问的只问一次并持久记住。
- **反例**：每次进入都问一遍语言偏好。

### D23 撤销是探索工具
- **判据**：保存后仍可撤销；撤销项写明动作名；对话框与直接操作共用撤销栈。
- **反例**：表格一保存即不可撤销。

### D24 触控与焦点
- **判据**：触控目标 ≥44×44pt（Android 48dp），间距 ≥8px；键盘焦点可见且不被遮挡；web 指针目标 ≥24×24 CSS px。

### D25 表单
- **判据**：每个输入有常驻 label（非 placeholder）；错误就近且说明修法；必填有标记；多步有进度与返回。

### D26 空状态与错误
- **判据**：空屏必须给"这是什么 + 下一步做什么"；错误不得只写"出错了"。

## 七、动效

### D27 只做一次编排
- **判据**：每屏动效元素 ≤1–2 个；不做逐节 fade-slide-up、不做每卡 hover。
- **例外**：列表加载（非首屏）允许 30–50ms 单项延迟。

### D28 动效必须表意
- **判据**：每个动画能说出它表达的因果关系（从哪来、到哪去、改变了什么）；退场为入场 60–70%；只动 transform/opacity。

### D29 尊重 reduced-motion
- **判据**：`prefers-reduced-motion` 下停用非必要动画；关键状态变化改为瞬时切换。

## 八、反模板黑名单（交付前逐条打勾）

- [ ] 不是"暖米色 + 高对比 serif + 陶土橙（≈#D97757）"三件套
- [ ] 不是"近黑底 + 单一荧光绿/朱红"
- [ ] 不是"报纸细线 + 零圆角 + 密排多栏"
- [ ] 不是 SaaS 卡片包：内容切成一模一样的圆角卡、统一阴影 `rgba(0,0,0,.1)`、渐变当装饰
- [ ] 不是模板外壳：ALL-CAPS eyebrow、`A · B · C` 中缀点、`WORD — fragment`、`#0B0B0B` 假黑、monospace 小标签、链接末尾 `→`
- [ ] 没有 Hero → 3 卡片 → 数据条 → CTA 的民主布局
- [ ] 没有标题里单独一个词变色/斜体
- [ ] 没有玻璃拟态 + 酸绿/紫蓝渐变

### D30 签名元素
- **判据**：全页只有一个"被记住的那一下"，其余安静；删掉任何一个装饰，若不影响理解就删。
- **反例**：每屏都有三个强调块，等于没有重点。

---

## 九、交付自检（设计层）

1. Design Read 4 问齐全，第 4 问有具体物件
2. 黑名单 8 条全过
3. 对比度实测（正文 4.5:1 / 大字 3:1）
4. 键盘 Tab 一遍，焦点不丢、不被遮挡
5. 375px 与横屏各看一次，无横向滚动
6. reduced-motion 开一次，页面仍可用
7. 触控目标 ≥44px，安全区不遮内容
8. 空状态、错误态、加载态三态都有
9. 签名元素能被陌生人指出来
